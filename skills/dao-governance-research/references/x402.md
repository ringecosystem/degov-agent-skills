# x402 payments against the Degov Agent API

## How it works

The Degov Agent API charges for standard/plus endpoints with [x402](https://docs.x402.org) on Base
in USDC. The flow (exact scheme, EIP-3009):

1. The client requests a paid resource. The API replies `402 Payment Required` with a base64
   `PAYMENT-REQUIRED` header (x402 v2) describing one payment option: `scheme: exact`,
   `network: eip155:8453`, `amount` (atomic units), `asset` (USDC on Base), `payTo` (the API
   receiver), and `extra` with the EIP-712 domain (`name`, `version`) and
   `assetTransferMethod: eip3009`.
2. The client builds an EIP-3009 `TransferWithAuthorization` typed-data message for that exact
   option (random 256-bit nonce — no RPC needed) and signs it.
3. The client retries the request with the `PAYMENT-SIGNATURE` header (x402 v2 envelope). The API's
   facilitator settles the transfer on-chain and returns the resource plus a `PAYMENT-RESPONSE`
   settlement header (tx hash).

Verified against staging (2026-08): the degov offers are standard x402 v2 with the EIP-712 domain
present in `extra` — this satisfies the MetaMask agent-wallet skill's `x402_pay.py` requirements, so
that script pays the Degov API **as-is** (no fork needed).

## Payment ceremony

Payments are executed by composing with the **MetaMask agent-wallet skill**
(`npx skills add metaMask/agent-skills`), which owns the `mm` CLI documentation and the
`x402_pay.py` ceremony script. Do not re-implement the protocol.

1. Load the metamask-agent-wallet skill; resolve its `scripts/x402_pay.py` path from that skill's
   directory.
2. Inspect first (read-only, no signing, no spending), and show the user the result:

```bash
python3 "$METAMASK_SKILL_DIR/scripts/x402_pay.py" inspect <paid-url>
```

3. After the user confirms the asset, amount, network, `payTo`, and resource URL:

```bash
python3 "$METAMASK_SKILL_DIR/scripts/x402_pay.py" pay <paid-url> --confirm
```

`pay` signs the EIP-3009 authorization with `mm wallet sign-typed-data`, retries with the payment
header, and prints the settlement (`transaction`) plus the resource body. If the `402` offers
multiple eligible options, select with `--asset` or `--network`.

## Rules

- **Confirm with the user before every payment** — a signature authorizes a real USDC debit.
- **One payment attempt per resource.** `x402_pay.py` is stateless: each run signs a fresh
  authorization. Re-running `pay` for the same resource makes a new payment. Never auto-retry a
  payment.
- A settled resource returns a `PAYMENT-RESPONSE` header — do not pay again for the same resource in
  the same session.
- The script requires `https://` (plain `http` is allowed only on loopback, which covers local
  staging like `http://127.0.0.1:8310`).
- Do not follow cross-host redirects; a redirected `402` should not be paid.

## Prerequisites for the paid path

- `mm` CLI installed: `npm install -g @metamask/agent-wallet`. When compatibility is in doubt,
  compare `mm --version` with the current MetaMask agent-wallet skill guidance.
- MetaMask agent-wallet skill installed.
- `mm doctor` → `authenticated: true` and `initialized: true`; Base (chain id `8453`) present in
  `mm chains list --json`.
- Base USDC balance in the mm wallet: `mm wallet balance --chain-ids 8453`.

If any prerequisite is missing, offer the web-only path instead of improvising a payment.
